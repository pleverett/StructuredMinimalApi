# .NET 10 Upgrade Notes

This document outlines the changes made during the upgrade from .NET 8.0 to .NET 10.0.

## Overview
- **Upgraded From**: .NET 8.0
- **Upgraded To**: .NET 10.0
- **Upgrade Branch**: `upgrade/dotnet-10`
- **Upgrade Date**: February 2026

## Breaking Changes

### 1. OpenAPI Configuration Changes
**Issue**: The `WithOpenApi()` extension method is deprecated in .NET 10 (ASPDEPR002).

**Old Approach** (.NET 8):
```csharp
var endpoints = app.MapGroup("")
    .AddEndpointFilter<RequestLoggingFilter>()
    .WithOpenApi();

// Authorization group with JWT security scheme
return app.MapGroup(prefix ?? string.Empty)
    .RequireAuthorization()
    .WithOpenApi(x => new(x)
    {
        Security = [new() { [securityScheme] = [] }],
    });
```

**New Approach** (.NET 10):
```csharp
var endpoints = app.MapGroup("")
    .AddEndpointFilter<RequestLoggingFilter>();

// Authorization group - OpenAPI auto-generated
return app.MapGroup(prefix ?? string.Empty)
    .RequireAuthorization();
```

**Resolution**: 
- Removed all `WithOpenApi()` calls from `Endpoints.cs`
- Removed manual `OpenApiSecurityScheme` configuration
- OpenAPI metadata is now auto-generated by .NET 10's built-in OpenAPI support
- No code changes required in endpoint implementations

### 2. Microsoft.OpenApi.Models Namespace Removed
**Issue**: Swashbuckle 10.x no longer directly exposes `Microsoft.OpenApi.Models` namespace.

**Resolution**: 
- Removed `using Microsoft.OpenApi.Models;` from `Endpoints.cs`
- Removed manual OpenAPI security scheme configuration
- Using .NET 10's standard OpenAPI approach instead

## Compatibility Notes

### FluentValidation 12.x
FluentValidation was upgraded from 11.9.2 to 12.1.1. Review the [FluentValidation 12.0 release notes](https://github.com/FluentValidation/FluentValidation/releases/tag/12.0.0) for potential breaking changes in validation rules.

### Swashbuckle 10.x
Swashbuckle.AspNetCore was upgraded from 7.2.0 to 10.1.3. The new version aligns with .NET 10's built-in OpenAPI support and removes direct dependency on Microsoft.OpenApi.Models.
